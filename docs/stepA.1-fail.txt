    This is a database stress-testing application on python.

It supposed to be adaptable to various different database engines, implementing only Postgresql one for now.
The query templates are generated based on grammar, to extract repeatable parts of the grammar into a cycle and turn it into (prefix, left, middle, right, suffix) tuples.
The grammar-generator logic is described at @docs/step5.txt and @docs/step5.1.txt

The generator right now is incorrectly handle non-trivial rules, where loops consists from not direct links, but from sequence.

The minified example grammar is provided in @tests/recursive_sample.y:

```
%%
stmt: 'PREFIX' A 'SUFFIX';
A: '{' B '}' ;
B: '(' C ')' ;
C: '[' A ']' 
   | 'MIDDLE' ;
```

The grammar defines the rules, where 'MIDDLE' should be surrounded by aligned brackets of a certain sequence.
The messages that are correct for the grammar:

```
PREFIX { ( MIDDLE ) }
PREFIX { ( [ { ( MIDDLE ) } ] ) }
PREFIX { ( [ { ( [ { ( MIDDLE ) } ] ) } ] ) }
```

But the template generated by the current logic is:

QueryTemplate(prefix='PREFIX { ( ', left='[ ', middle='MIDDLE ', right='] ', suffix=') } SUFFIX')

which correctly identifies prefix and suffix sequence, but repeatable LEFT and RIGHT are incorrect: they are just square brackets, while they should be square-curled-round brackets sequence.
