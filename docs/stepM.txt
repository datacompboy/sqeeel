This is a database stress-testing application on python.

It supposed to be adaptable to various different database engines, currently have working engines for Postgresql and MariaDB.

You've implemented:
 - sqeeel/database_modules, providing running the database engine and running queries against it using docker-based images;
 - sqeeel/template_instantiator module, that allows to generate queries that are scalable in size;
 - sqeeel/query_generator module that generates query templates based on a bison-style grammar parser tuned to the database calling database module hooks;
 - sqeeel/stress_engine, that applies each given template running stress loop over whole range of sizes;
 - runner application with CLI interface;
 - some limited unit tests in tests/ directory.

Now we need to add support for CockroachDB. The grammar is similar and based on the PostgreSQL, the grammars/cockroachdb-sql.y file is there
with the latest version from CockroachDB repository (do not try to read grammar files, they are huge, ~500kb); but we can assume for start it's
same as PostgreSQL.

Since that a distributed database, we should find a way to provide multi-container database setup: create network, run multiple containers, run init
on one of them. The health/crash check should check status of status of all containers running; or check all running and check the list list all containers...

The up to date instruction on how to run multi-node cluster, consult with https://www.cockroachlabs.com/docs/stable/start-a-local-cluster-in-docker-mac#start-a-single-node-cluster

We should not create volumes, as the goal is to run ephemeral system -- in case of any failure we restart system from scratch.

Please plan and propose the solution, before going to implement it.
